## 0. 结论先行：五条判断

| # | 判断 | 依据 |
| --- | --- | --- |
| 1 | **双端不是"同一套页面两个壳"，是两种使用姿势**。网页＝书桌整理（大屏、批量、校对、发布）；APP＝碎片复习（单手、离线、快）。职责要对齐，功能不必强求 1:1。 | 网页端 JS 只有 154 行，4 个 tab（矩阵/反查/复习/数据），矩阵只读；APP 已 5 个 tab 且有编辑、冲突裁决。现在不是"两端一致"，是"一端领先一代"。 |
| 2 | **真正的瓶颈不是编辑，是录入和复习闭环**。编辑面板解决"改一个字"，但"把教材搬进来"仍要手工敲 17 个字段。 | 领域包 17 字段（6 个 immutable 只能照抄原文、11 个可编辑）；APP 里录一味药要切 17 次输入框。 |
| 3 | **掌握度有两个真相**：`mastery` 是手工文本字段，SRS 又从复习事件算出状态。两套互不同步，`diff` 视图还按手工值过滤。 | `materia-medica.toml` 的 `mastery`（text，个人字段）+ `fold_events(Sm2Scheduler)` 各算一套；`diff` 视图 `filter = {field="mastery", op="ne", value="熟练"}`。 |
| 4 | **"原样字段不可改"只有半条路**：能拦住改，但没有"新建条目"入口，用户被卡死。 | `apply_edit` 会拒绝 immutable；APP 只有编辑对话框，没有"新建/复制为新条目"。 |
| 5 | **数据主权是卖点，但凭据存储还不合格**：token 明文躺在 `shared_prefs` 和 `sync.json`。 | 实测 `run-as cat sync.json` 可直接读出 PAT；网页端 token 走请求头 + localStorage。 |

## 1. 产品定位与成功标准

**一句话**：把教材变成"可练、可改、可同步、可导出"的个人记忆库，并且允许多个领域共用同一套内核。

**明确非目标**（写下来是为了拒绝需求）：

- 不做多人协作 / 团队空间 / 权限体系（单人使用，最多"我一台电脑 + 一部手机 + 未来一台平板"）
- 不做云端托管服务（不运营服务器，同步只借用 GitHub 私有仓库）
- 不做通用卡库 / Anki 替代品（Anki 只作为导出目标）
- 不做社交、分享、排行榜

**成功标准（都可测）**

| 指标 | 目标 | 测法 |
| --- | --- | --- |
| 录入一味药 | ≤ 2 分钟（含 15 字段） | 真机计时，从点"新建"到保存 |
| 每日复习 | 当日到期清空 ≤ 15 分钟 | 连续 7 天，记录到期数与用时 |
| 误改恢复 | ≤ 30 秒 | 改错 → 撤销 → 值回到原样 |
| 换设备恢复 | ≤ 5 分钟 | 新设备装 APP → 填凭据 → 拉取 → 看到同样的卡 |
| 冲突不丢数据 | 100% | 构造 20 组冲突，逐项裁决，比对落库值 |

## 2. 用户与场景（决定优先级）

| 场景 | 设备 | 时长 | 关键约束 | 现在能不能用 |
| --- | --- | --- | --- | --- |
| **A 通勤刷** | 手机，单手，可能无网 | 5–10 min | 一屏一张卡、大按钮、不依赖网络、随时中断 | 能（复习页），但无每日配额、无错题集中 |
| **B 书桌整理** | Win 网页 + 教材/PDF 并排 | 30 min+ | 键盘操作、批量、多窗口对照、快速校对 | **不能**（网页矩阵只读，无编辑） |
| **C 考前查漏** | 手机/网页 | 20 min | 按"不熟练/易混"聚合、对比相似药 | 半能（`diff` 视图按手工 mastery 过滤，数据不可靠） |
| **D 维护公共库** | Win + CLI/网页 | 偶发 | 改基础内容 → 出 bundle → 发布 → 别人拉到 | 能（CLI `upstream-publish`），网页无入口 |

> **场景 B 是当前最大缺口**：用户明确说"Win 端用网页"，但网页端现在只能看和导，不能改。这是 M1 必须补的。

## 3. 双端职责划分

原则：**数据能力两端等价，交互形态各自最优**。凡是"会改数据"的操作，两端都必须能做；凡是"效率型"的操作，只在合适的端做。

| 能力 | 网页 | APP | 理由 |
| --- | --- | --- | --- |
| 装载/切换领域包 | **主** | 自动（内置 assets） | 网页可拖入 TOML；手机预置即可 |
| 新建条目 | **主** | 次 | 大屏一次填 17 字段才现实 |
| 编辑字段 | **主** | 次（已实现） | 同上 |
| 批量导入（CSV/JSON/粘贴） | **主** | 辅 | 键盘 + 剪贴板 + 多窗口 |
| 拍照 OCR 录入 | — | **主** | 只有手机有摄像头 |
| 矩阵浏览/筛选 | 主（宽表） | 次（窄屏，列裁剪） | 屏幕宽度决定 |
| 反查 | 主（可多线索并行） | 主 | 两端都常用 |
| 复习 | 辅（书桌预习） | **主**（通勤） | 场景决定 |
| 冲突裁决 | **必须完整** | **必须完整**（已实现） | 数据安全不能因为"换了个端"就无法处理 |
| 历史/撤销 | 主 | 只读查看 | 复杂操作在大屏做 |
| 发布公共库 bundle | **主**（网页按钮）/ CLI | — | 维护者动作 |
| 同步配置 | 主 | 主（已实现） | 两端都要能改凭据 |
| 导出 | 主（7 种格式） | 辅（1 种即可） | 文件落盘在电脑上更方便 |

**必须两端一致的三条**（不可妥协）：

1. 同一个库、同一份数据（不是两份各自为政）；
2. 冲突必须"逐项、三值并列、未决不写"；
3. `immutable` 字段在任何端都改不了，且提示"需新建条目"。

### P0-2 复习闭环（M2）

现在只有"取到期卡 → 答 → 手动选 3 档"，缺 4 件事：

| 功能 | 说明 | 验收 |
| --- | --- | --- |
| 每日队列 | 到期卡 + 新卡上限（如 到期 50 / 新 10），当日不再增长 | 一天内多次进入，题目集合稳定 |

| 错题本 | 连续答错 ≥2 次的卡进"薄弱"集合，单独入口 | 能从错题本开始一轮复习 |
| 掌握度派生 | `mastery` 由 SRS 状态计算（三档），不再手工填 | 复习 3 次后矩阵里 mastery 自动变化 |

> 这一条同时解决 §0 判断 3 的"双真相"问题：**mastery 变成派生值，写回字段只用于展示与视图过滤**。

## 5. 关键流程（含验收点）

### 5.1 首次上手（目标：3 步内看到第一张卡）

```
打开 APP → 看到内置领域包列表 → 点「中药学」→ 导入示例 6 味 → 进复习页看到第 1 张卡
```
**验收**：不填任何凭据、不联网也能完成；耗时 < 60s。

### 5.2 录入一味药（两条路径）

- **路径 A（网页，推荐）**：新建 → 粘贴教材段落 → 自动映射 → 校对 immutable 6 项 → 保存
- **路径 B（手机）**：拍照 → OCR → 草稿卡 → 逐字段确认 → 保存

**验收**：路径 A ≤ 2 分钟；路径 B 单页 ≤ 3 分钟（含校对）；保存后立刻能在矩阵和反查里查到。

### 5.3 每日复习

```
进复习 → 显示"今日 12 张（到期 8 / 新 4）" → 答题 → 判分 → 自动建议评分 → 下一张
→ 全部完成 → 显示"今日完成，明日 9 张到期"
```
**验收**：中途退出再进，进度不丢；同一张卡当天不重复出现（除非答错）。

### 5.4 拉公共库（已有，需在网页端复刻）

```
拉取 → 有冲突则每项三值并列 → 逐项选（保留我的/采用上游/两者都留/自定义）
→ 未全决定前"提交"禁用 → 提交后落库 + 决策日志进私有库
```
**验收**：未决时提交按钮不可点，且后端也拒绝写入（双重保障）；决策日志能在私有库 `sync/upstream-decisions.jsonl` 查到。

### 5.5 误改撤销

```
编辑面板 → 保存（误改）→ 顶部出现"已保存 1 项 · 撤销" → 点撤销 → 值回滚，rev +1（不是 -1）
```
**验收**：撤销后矩阵、反查索引、卡片全部一致（不能只改字段不重建索引）。

### 5.6 换设备恢复

```
新设备 → 填 token/owner/repo → 保存并启用 → 拉取（首次全量）→ 重建索引与卡片 → 可复习
```
**验收**：设备 B 拉完后 `state.entities/cards/rev` 与设备 A 一致；不重复产生事件。

## 6. 数据与协议规则（必须写死的部分）

### 6.1 字段三级权限

| 级别 | 定义 | 谁可改 | 例 |
| --- | --- | --- | --- |
| `immutable` | 教材原文，禁止同义替换 | **无人可就地改**；只能新建条目 | 性味归经、毒性、用量、配伍禁忌、特殊煎法、相似药鉴别 |
| `base` | 公共基础内容 | 本地可改（记为个性化），上游可更新 | 药名、药群、功效、应用、特点锚、教材主表述 |
| `personal` | 只属于我 | 只本地，**绝不进公共库** | 掌握度、同义说法、不可替换边界、笔记 |

> 现状核对：`topology.personal_fields` 里有 `notes`，但 `materia-medica.toml` **没有定义 notes 字段** —— 用户"写点自己的话"没地方写。M2 补 `notes`（text, 多行, personal）。

### 6.2 掌握度派生规则（收敛双真相）

```
SRS 状态 → 三档：
  stability < 1d 或 连续错 ≥2   → 生疏
  stability < 7d               → 熟悉
  stability ≥ 7d 且 最近一次评分 ≥3 → 熟练
```
- 派生值写回 `mastery` 字段（只读，UI 不可手填）
- `diff` 视图继续按 `mastery != 熟练` 过滤，但数据源变成派生值
- 保留手工覆盖开关（"我就是要标成熟练"），覆盖后 30 天内不被派生值改写

### 6.3 删除与修订

- 删除 = `Tombstone`（显式墓碑），**绝不靠"远端没有"推断删除**（已踩过）
- 30 天内可恢复；超过后由用户手动"清理回收站"
- `immutable` 字段要改 → 新建条目并填 `supersedes = 旧 id`，旧条目自动加"已被替代"标记（视图可隐藏）

### 6.4 冲突默认策略

| 场景 | 默认建议 | 理由 |
| --- | --- | --- |
| 两边都改，本地值 ≠ 基线 | 保留我的 | 个性化优先 |
| 无基线（首次接入/旧数据） | 保留我的 | 不猜，宁可多问 |
| `immutable` 字段两边不同 | 保留我的 + 红标 | 教材原文不能被我覆盖掉 |
| 上游移除但本地改过 | 保留我的 | 不静默删数据 |
| 上游新增实体 | 自动加入 | 没有歧义 |

### 6.5 版本与迁移

- 领域包 `schema` 加字段：旧实体缺该字段视为空，不报错
- 领域包删字段：数据保留在库里但 UI 不显示（**不删数据**）
- bundle 格式加 `format: mneme-bundle/1` 版本号，读旧版要兼容

## 9. 待你决策（按影响排序）

1. **网页端形态**：`mneme serve` 本地进程（现状，简单、可局域网访问）/ PWA 纯前端（能离线，但要重写数据层到 WASM 或 IndexedDB）/ 两者都要（PWA 只读 + 本地进程可写）。
   → 我的建议：**本地进程先做全功能**，PWA 放 P2；理由是 WASM 版 SQLite + 事件日志是另一个工程量级。
2. **复习算法**：继续 SM2 / 切 FSRS（已有实现，需接 `fit()` 与迁移旧状态）。
   → 建议：**先 SM2 跑通闭环**，攒够 ≥200 条复习事件后再切 FSRS，避免早期数据污染参数。
3. **`immutable` 字段改错的出路**：只允许"新建并替代" / 允许"修订本"（同一味药多个版本，可切换）/ 允许直接改但强制留痕。
   → 建议：**新建并替代**，与现有"原样字段"哲学一致，且不需要新表。
4. **掌握度**：完全派生（不可手填）/ 派生 + 手工覆盖 / 保持手工。
   → 建议：**派生 + 手工覆盖（30 天有效期）**。
5. **多领域**：一个库支持多 schema（切换视图） / 一个领域一个库（现状）。
   → 建议：**一个领域一个库**，切换时换目录；跨领域检索放 P2。
6. **删除保留期**：30 天 / 永久（只能恢复不能清） / 立即物理删。
   → 建议：**30 天**，回收站入口放设置页。
7. **APP 文件导入**：要不要支持从"文件管理器选 CSV"（现在只有粘贴 + OCR）。
   → 建议：要，P1；手机拍完 OCR 之外，还得能接收电脑导出的 CSV。
